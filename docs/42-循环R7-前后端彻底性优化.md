2. 装饰线/导轨/虚线占位框/节点圈 → `var(--color-border-guide)`（8 处）。

### 11.12 关掉 11.9 登记的"非文案缺陷"：`safeError()` 吞掉了服务端原因

11.9 末尾记了一条**不是文案**的缺陷：`enterprise-content-recovery/ContentRecoveryPage.tsx`
的 `safeError()` 无条件返回固定串，用户永远看不到服务端给的原因。本轮落地。

**为什么能在不新增脱敏逻辑的前提下修**（三条都是读出来的，不是猜的）：

1. 该模块**自己就有**尺子：`model/recoveryModel.ts:906` 的
   `sanitizeRecoveryMessage(value, fallback)` —— 非字符串 / >512 / 控制字符 /
   `SECRET`（含 `bearer\s+`）/ `URL` 任一命中就回落到 fallback。
2. **没有跨模块借道**：全仓 `grep` 确认零个模块 import 过
   `enterprise-knowledge-base-release/` 的 `safeReleaseDisplayText`，
   所以不去引那一版，改用本模块自己的同名职责函数，模块边界不破。
3. **为什么显示层还要再过一次**：`api/recoveryApi.ts:397-403` 里
   `projectPage(...)` 挂在 `safeRequest(...).then()` 上，**在 `safeRequest` 的
   try/catch 之外**，因此投影期抛出的本地错误从来没被 `sanitizeRecoveryMessage` 过。
   这一层不是冗余保险，是必要的一遍。

```ts
const RECOVERY_ERROR_FALLBACK = "企业内容恢复权威不可用";
function safeError(error: Error | null): string | null {
  return error ? sanitizeRecoveryMessage(error.message, RECOVERY_ERROR_FALLBACK) : null;
}
```

固定串保留为 fallback，因此**没有任何既有断言需要改**（全仓 `企业内容恢复权威不可用`
只出现在定义处一处）。

**顺手补上真正的洞**：该模块 5 个 `safeError` 调用点（summary / entries / detail /
retentionPolicy / mutation）在测试里**全是 `error: null`**——整条错误面零覆盖，
这正是缺陷能活下来的原因。补两条用例：安全原因要透出来、带 `Bearer` 的消息必须回落且
`queryByText(/Bearer/)` 为 `null`。为此把内联 fixture 提成 `const baseHook` 并在
mock 的 center 桩里多渲染一个 `controller.entries.error`。

**验收状态：本小节改动尚未跑门禁**（写它时后端全量正独占机器），
与 11.11 之后的 anime 主色族改动一起排队复跑。

**顺手记下但本轮没动的一处结构问题（且我最初的诊断是错的，已纠正）**：
这两个模块把自绘的 `<span role="tab" tabIndex=0 onClick=…>` 塞进 TDesign `<Tabs>` 的 `label`，
而父级 `Tabs` 也有 `onChange`——一次点击确实挂在两层（两处都调 `setTab`，幂等，危害低）。

真正的缺陷方向相反：**它是不完整的 ARIA**——`role="tab"` 没有被 `role="tablist"` 拥有，
也没有 `aria-controls` ↔ `role="tabpanel"` 关联，按 WAI-ARIA 属孤儿角色。
规模是 **18 个文件 / 21 处 `role="tab"`**（含一个叫 `AccessibleTabLabel.tsx` 的组件）。

修法（补全 ARIA vs 降级成 `<button aria-pressed>`）留在 task #17 待定。
详见 `findings.md` §24。

**验收状态：本小节 4 处 CSS 改动尚未跑门禁**，与 11.11 之后的 anime 主色族、
11.12 的 `safeError()` 一起排队（task #10）。

### 11.14 把"读屏念不念得出来"变成可量维度：门禁只量看得见的一切

11.13 里发现孤儿 `role="tab"` 之后追问一层：这一维**从来没被任何门禁量过**，
不是没人关心无障碍，而是仪器的全部维度（对比度、部件对比度、触控、溢出、裁切、混排）
都是"肉眼可见"的，没有一维检查 DOM 的语义结构。
于是补两维，都只打印、不设阈（无实测值就设阈等于拍脑袋，与 §10 的教训冲突）：

| 维度 | 判据 | 分母 |
|---|---|---|
| `ariaTabStructureViolations` | 每个可见 `[role="tab"]`：无 `[role="tablist"]` 祖先 → `no-tablist`；无 `aria-controls` → `no-aria-controls`；指向不存在的 id → `dangling-aria-controls`；指向的元素不是 `role="tabpanel"` → `controls-not-tabpanel` | `ariaTabs`（可见 `role=tab` 数） |
| `missingAccessibleNames` | 每个可见 `input/select/textarea`（排除 `type=hidden` 与 `aria-hidden` 子树）：既没有 `label[for]`、也没有包裹式 `<label>`、也没有 `aria-label`/`aria-labelledby`/`title` | `formControls`（被检控件数） |

两维各带样本（`sel` + 归类 + 上下文：tab 带文本、控件带 `placeholder`），
所以第一次跑出来的不只是"有多少"，还有"是哪些、缺在哪一环"。
`placeholder` 特意进样本：**只有占位符的输入框按这一维算不合格**
（占位符随输入消失、颜色也常被做浅），把它和"完全没名字"区分开是后续清理的排序依据。

预期这一维会给出一个不小的数字，因此首跑之后要做的是：按实测上界 + **分母下界**一起写进
`verify_all.ps1`（只锁上界等于允许"少量一点"来伪装进步，就是 §22 刚犯过的错）。
登记为 task #18；背后的结构性修法在 task #17。

### 11.15 读别人的计划时，`[ ]` 不等于"没做"：reduced-motion 的一真一假

1. **先证明这个文件会被加载**才动手：`main.tsx:10` 确实 import 了 `theme/anime.css`

### 11.19 剩下 81 处的执行契约（用户 2026-09-20 已裁定，含实测规格与两个必须避开的坑）

**裁定**：`/enterprise/tasks` 与 `/enterprise/automations` 的自绘 `<span role="tab">`
**迁到兼容层 `Tabs`，并把 TDesign 页签样式移植成 `.rag-tabs`，视觉不变**。
用户明确否决"保留 TDesign 视觉、删掉 span 的 `role=tab`"——那会让指标归零而实际是**删无障碍语义**。

**为什么不能"就地补全"**：两个模块都是 `import { Alert, Tabs } from "tdesign-react"`（各自 :2）**绕过 facade**，
span 塞在 `Tabs.TabPanel` 的 `label` 里，其父级是 TDesign 自己的 nav DOM，我们既拿不到它加 `role="tablist"`，
也拿不到面板元素加 `id`。而 TDesign `TabNavItem.js` 的 `aria-` 命中数是 0 —— 所以只能换渲染方。

**坑一：挂载语义不同，直接迁会引发重新发请求。**
`node_modules/tdesign-react/esm/tabs/TabPanel.js:34-43` 的实测语义是
**lazy-then-keep-mounted**：面板首次激活才挂载，之后留在 DOM 里靠 `display:none` 隐藏。
兼容层 `Tabs` 现在只渲染当前 `items.find(...)?.children`，切走即卸载。
照字面迁移 = 切回页签重新挂载、重新发请求、丢滚动与筛选态（`AutomationCenter.test.tsx:321`
"loads each lazy authority collection when its tab becomes active" 正是这个语义）。
→ 给兼容层加**opt-in** 的 keep-alive（默认关，保住现有十余个调用点与 `/visualize` 的行为不变）：
仍然只渲染**一个** `role="tabpanel"`（所有 tab 的 `aria-controls` 指向它，与 R13 已测结构一致），
面板内部把"曾激活过"的 item 堆叠渲染、非当前的加 `hidden`。
这样既不加第二个 panel id、也不产生 `dangling-aria-controls`。

**坑二：aria-controls 不能按 key 各造。** 未激活过的面板不在 DOM 里，
按 `item.value` 生成会让那些 tab 指向不存在的元素——把 `no-aria-controls` 换成 `dangling-aria-controls`，数字不降反可能升。

**纠正我此前写进记忆里的那句话**：`project-rag4c-rounds-and-rulings.md` 记的是
"两边各有一份**同值**规则，今天没有可见 bug，陷阱在于改到不生效的那一份"。
按字面量等价归一后重新核对：**5 组确实等价（含只差 `!important` 的 2 组），
只有 1 组是真的不同值** —— 菜单分组标题的 `#c9a8b5`（实际生效）vs `#7a5f6c`（anime.css 里那份，永不生效）。
所以"改错份就白改"这个陷阱成立，但"今天完全没有可见差异"这句要收窄到那 1 处：
它不是可见 bug，而是**两个意图并存且互相矛盾**，谁下次照着 anime.css 调分组标题颜色就会白改。

对第 0 步的直接含义：合并 anime 权威源时**不能机械删除 anime.css 的副本**，
因为分组标题那一处需要先定"该听谁的"（属用户判断，不是我能自行决定的视觉口径）。
另需注意：脚本按"特异度→加载顺序"决胜，`anime.css` 头部注释"最后加载以取得最高优先级"
在两边同特异度时才成立；今天这 6 组里 styles.css 靠**重复类**把特异度抬了一位，所以加载顺序根本不参与决胜。
