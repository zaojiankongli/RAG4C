# RAG4C 数据管道说明

本文梳理 RAG4C 的数据管道全貌（2026-08 当前代码状态），包含两条主干：

- **写入管道（Indexing）**：文档文件 -> 知识库索引（Milvus + 图 + 目录状态）
- **查询管道（Querying）**：用户问题 -> 有据可依的回答（引用 + 验证 + 弃权）

配套数据流图：
- 全管道总览：docs/rag4c-dataflow.html（archify 生成）
- 数据入库处理流程（详细，仅数据进来这一段）：docs/rag4c-ingest-flow.html

## 1. 写入管道：文档 -> 知识库

### 1.1 入口与登记

| 入口 | 说明 |
|---|---|
| `POST /api/documents/ingest` | 桥服务登记文档（server/documents.py），由有界入库执行器异步执行 |
| `catalog.create_document` | 写入 SQLite documents 表（状态 waiting、文件路径、doc_type） |
| 幂等 | 同 dataset+file_path 已完成文档直接返回；增量变更走 /reindex |

### 1.2 DeepDoc 双引擎解析（indexing/parsers/）

```
PDF -> DocumentRouter.route（pdf-inspector 采样分类，10-50ms）
  text_based（约 54%）  -> Fast 引擎：pdf-inspector（纯 Rust 提取 + Markdown 化，~200ms，零 OCR）
  scanned / image_based -> Vision 引擎：MinerU（mineru-open-api flash-extract，OCR + 版面识别）
  mixed                 -> MVP 整本走 Vision（页级路由数据 pages_needing_ocr 已预留）
非 PDF（docx/pptx/xlsx/图片） -> Vision 引擎
```

产物：`ParsedDocument{ text, pages, layout, engine, metadata }`

- `layout`：10 种版面组件块（text/title/figure/figure_caption/table/table_caption/
  header/footer/reference/formula + 页码/bbox），供版面感知切分；
- 开关：`RAG4C_PARSERS_ROUTER_ON` / `PDF_INSPECTOR_ON`（关闭后行为同旧版全走 MinerU）。

### 1.3 清洗与预切分

- `cleaner.clean(text)`：文本清洗（可选组件）；
- `strategy.chunk(text)`：按 doc_type 选择预切分策略，产出章节级 **segments**
  （DocumentSegment 粒度，分段级进度追踪单元）。

### 1.4 结构化切分（chunker）

`StructureAwareChunker.chunk_document` 逐段切分，产出 `Chunk`：

- `chunk_id` 由内容确定性生成（同输入必同 id——增量重索引的基石）；
- `text_hash` = sha256(text)（L2 引用验证 + 差量对比共用）；
- 层级链：Document -> Chunk -> ChildChunk（`parent_chunk_id`）；
- 统一写入 `tenant_id` / `dataset_id`（多租户 + 知识库维度）。

### 1.5 元数据加工（三个可选增强，按开关注入）

| 增强 | 模块 | 开关 |
|---|---|---|
| TSR 表格结构识别（5 标签 + LLM 友好句子） | indexing/parsers/tsr.py | `RAG4C_PARSERS_TSR_ON`（默认关） |
| 自动打标签（通道 B：classifier 槽位按分类体系输出 JSON 标签，非法键/类型丢弃） | indexing/auto_tagger.py | `RAG4C_CATALOG_AUTO_TAG_ON`（默认关，待装配进 ingest） |
| Contextual Retrieval（文档级定位上下文写入 metadata.context） | indexing/contextual.py | 构造注入 contextualizer |

### 1.6 嵌入与写入（Milvus）

- 稠密向量：BGE-M3（`embedder.embed_texts`，provider=api/local）；
- 稀疏向量：**Milvus 内置 BM25 Function 在写路径自动生成**（应用层不产 sparse）；
- 写入集合 `rag4c_chunks`：chunk_id(主键) / doc_id / text(analyzer) / text_hash /
  created_at / updated_at / source / parent_chunk_id / acl / tenant_id /
  dataset_id / metadata(JSON) / dense_vector / sparse_vector。

### 1.7 图谱索引（可选）

`graph_builder.build` 对 chunk 文本做三元组抽取（triplet 槽位），实体写入
`rag4c_entities`、关系写入 `rag4c_relations`（独立集合，passage 角色回查
chunks 集合避免文本双写）。

### 1.8 状态机与进度（贯穿全程）

```
waiting -> parsing -> splitting -> indexing -> completed
                 └---- 任一点失败 ----┴----> error（retry 从 error 重入）
```

- 双粒度进度：文档级 progress 0..1 + 分段级「第 N/M 段」（DocumentSegment 表）；
- 持久化：全部状态落 SQLite（catalog），进程重启后 waiting/error 可续跑；
- 装配：`DocumentIngestJob`（indexing/state_machine.py）桥接
  `IngestPipeline` 两段式（parse_and_chunk + embed_and_insert）与 catalog。

### 1.9 增量重索引（indexing/reindex.py）

```
文件 sha256 未变 且 completed 且未 force -> 跳过（零成本）
否则：reset(waiting) -> parse_and_chunk（新 chunks，不嵌入）
     -> 旧 chunks 按 doc_id+tenant 查询
     -> 差量：text_hash 未变 = 跳过嵌入（保留旧向量）
              新增/变更 = 重新嵌入 upsert
              旧有消失 = delete_by_ids
     -> 更新 catalog（chunk_count / file_hash）
```

## 2. 查询管道：问题 -> 有据回答

编排顺序（rag.py / rag_graph.py / rag_stream.py 三实现语义一致）：

```
gate -> rewrite -> route -> embed -> search -> [增强] -> diversity
     -> [图谱分支] -> rerank -> [sentence_window] -> top_k
     -> generate -> verify(L1/L2/L3) -> abstain -> [二轮补救] -> QueryResult
```

### 2.1-2.3 门控 / 改写 / 路由

- 复杂度门控：具体查询跳过改写与路由（零 LLM 成本）；
- 查询改写：rewrite 槽位，失败静默降级原文；
- 意图路由：嵌入相似度为主 + LLM 兜底；目标 `hybrid` / `vector_graph_rag` /
  `full`（图谱目标不可用时自动降级 hybrid 并标记 degraded）。

### 2.4 查询端增强（默认全关）

HyDE（假设文档）、SubQueries（子查询拆解）、Stepback（后退式提问）——
开关开启且注入组件才生效，失败一律静默降级只记 trace。

### 2.5 嵌入与混合检索

- BGE-M3 稠密 + Milvus BM25 稀疏，RRF 融合（candidate_factor 放大候选）；
- 过滤表达式（AND 组合）：tenant 无条件启用 + ACL 受 `acl_filter_on` 控制；
- **已建成待装配**：dataset_id 过滤（`build_filters` 已支持）、通道 A 自动
  过滤（LLM 生成表达式 + `validate_filter_expr` 白名单校验，组件就绪）。

### 2.6-2.8 多样性 / 图谱 / 重排

- 来源多样性：off / group_only / MMR（文档级去重）；
- 图谱分支：实体检索 -> 子图扩展 -> 关系检索 -> LLM 重排 -> passage 合并
  （与混合结果按 chunk_id 去重）；
- 重排：bge-reranker-v2-m3，失败保持原始顺序；SentenceWindow 父块回取（可选）。

### 2.9 生成 -> 验证 -> 弃权 -> 补救

- 生成：generation 槽位，强制 `[N]` 引用标记，越界编号剥离；
- 三层验证（verify/verifier.py）：
  - L1 存在性（引用的 chunk_id 在证据集中）
  - L2 哈希（text_hash 一致，防内容漂移）
  - L3 蕴含（judge 槽位 LLM 判定 claim 是否被证据支撑）
- 双阈值弃权：检索分数 + 蕴含分数不达标 -> `abstained=True` 空答案；
- 二轮补救：证据不足时重跑检索合并（MAX_ROUNDS=2，无新增证据防死循环）；
- 产物 `QueryResult{ query, answer, citations[status], verdict, abstained,
  route, traces }` + 桥服务附加 `evidence`（截断 400 字，来源卡片深链）。

## 3. 桥服务层（HTTP 入口，server/app.py）

| 机制 | 数据管道角色 |
|---|---|
| SSE 流式（/api/query/stream） | 阶段事件（retrieving/generating/verifying…）+ 逐 token；客户端断开即关闭底层 LLM 流 |
| 查询缓存 | tenant+query+排序 ACL+retry 相同则命中 10 分钟 TTL LRU（64 条）；并发 miss 使用 single-flight |
| 查询并发与超时 | 查询与 SSE 共用执行器；每进程并发 4 + 队列 20（429）+ 排队/执行统一 240s deadline |
| 入库并发 | 每进程有界执行器并发 2 + 队列 8（429）；同 doc 重复活动任务返回 409 |
| 熔断器 | retrieval / llm.generation 独立熔断，打开时 7ms 快速弃权 |
| 健康探活 | ok/degraded/down 三级 + 组件明细；5s 快照缓存与 single-flight，过期时可立即返回旧快照 |
| 最近查询 | 进程内 50 条环形缓冲（监控页回放 / 可视化页轨迹回放数据源） |
| 指标持久化 | 60s 快照 -> data/metrics-history.jsonl（5MB 轮转）+ /history + /prometheus |

## 4. 支撑层（贯穿两条管道的基础设施）

### 4.1 数据契约

`models/schemas.py`：Chunk / RetrievedChunk / Citation / QueryResult /
RouteDecision / JudgeResult / Triplet（全 pydantic v2，前后端对照）。

### 4.2 多租户目录（SQLite，core/catalog.py + models/orm.py）

```
Account -> Tenant -> App -> Workflow
              └-> Dataset -> Document -> DocumentSegment
```

含配额（quota_documents/chunks）+ 用量计数 + 元数据 schema 注册表
（MetadataField：键/值类型/来源 manual|auto）。

SQLite 使用 WAL、外键和 busy timeout；tenant/dataset 首次创建使用方言级
upsert。文档登记与文档配额占位在同一事务中完成，计数使用 SQL 原子增量。
chunk 配额仍在入库后按实际差量结算，尚未提供严格的预留/确认/失败补偿。

### 4.3 过滤表达式安全（core/metadata.py）

- 系统保留键 SYS_KEYS（tenant_id/dataset_id/doc_id/doc_type/page/chunk_level…）；
- 递归下降解析器：键白名单 + 值类型 + 语法校验，注入攻击 8/8 用例全拒；
- 通道 A（自动过滤）产物必经此校验；manual 条件经 filters_from_dict。

### 4.4 可观测性

- query_id 贯穿日志（contextvar）；
- trace spans -> 进程内指标（P50/P95/P99 + 错误率 + 熔断开合计数）；
- 访问日志中间件（慢请求 >10s 告警）。

### 4.5 持久化存储清单

| 存储 | 内容 | 路径 |
|---|---|---|
| Milvus 集合 rag4c_chunks | 检索单元（dense + BM25 sparse + 过滤标量 + metadata JSON） | settings.milvus |
| Milvus 集合 rag4c_entities / rag4c_relations | 知识图谱 | settings.milvus |
| SQLite | 租户关系 / 文档状态机 / 元数据 schema | data/rag4c.db |
| JSONL | 指标历史快照 | data/metrics-history.jsonl |
| .env | 运行时配置（原子写入 + 写锁） | 项目根 |

| 项 | 状态 |
|---|---|
| 写入/查询主干全链路 | ✅ 已接通（15/15 冒烟全绿，含真实 MinerU + pdf-inspector 集成） |
| 通道 A 自动过滤（LLM 表达式） | 组件就绪（retrieval/auto_filter.py + 校验器），**未装配进 RetrievalPipeline** |

| mixed PDF 页级混合拼接 | 预留（pages_needing_ocr 数据已产出） |
| NLI 验证模式 | 预留（当前 LLM 判定） |
| OTel 导出 | 占位 stub（无后端） |

并发控制、缓存、single-flight、最近查询和指标均为进程内状态。多 worker
部署时容量会按 worker 数量放大，且不得让多个 worker 共享同一 Milvus Lite
文件；详细配置和部署边界见 `docs/后端可插拔与高并发改造.md`。
