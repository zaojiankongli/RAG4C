## 3. core/ —— 基础设施

**文件**：`embedding.py` / `llm.py` / `reranker.py` / `milvus_client.py` / `tracing.py` / `retry.py` / `metrics.py` / `observability.py` / `graph_store.py`

### 3.1 嵌入（embedding.py）
- `EmbeddingService` 协议（embed_texts / embed_query）。
- `Bge3LocalEmbedder`：本地 FlagEmbedding BGE-M3，**只出稠密向量**（`return_sparse=False`，稀疏检索交给 Milvus 内置 BM25 Function）；模型惰性加载。
- `ApiEmbedder`：OpenAI 兼容 `/embeddings` 端点（可指向 vLLM / Ollama / 网关）。
- `create_embedder(cfg)` 按 provider 工厂创建。

### 3.2 LLM 槽位（llm.py）
- `LLMClient`：openai SDK 驱动任意 OpenAI 兼容端点；openai 为可选依赖（惰性导入）。
- `chat()`：普通对话；`json_mode` 端点不支持 `response_format` 时自动降级重试一次。
- `chat_json()`：要求 JSON 输出，解析失败带纠正指令重试一次，仍失败抛 `ParseFallbackError`（**绝不静默返回 None**）。
- **已接入重试**（core.retry）：瞬态异常 `APIConnectionError` / `APITimeoutError` / `RateLimitError` / `InternalServerError` 自动重试；400 等非瞬态错误不重试，直接走 json 降级路径。

### 3.3 重排序（reranker.py）
- `Reranker` 协议（rerank(query, candidates) -> list[float]）。
- `BgeReranker`：本地 FlagReranker（BGE-reranker-v2-m3），惰性加载。
- `LlmReranker`：LLM listwise 打分槽位（分 batch、可 `fallback_on_error` 退化为等分）。

### 3.4 Milvus 客户端（milvus_client.py）
- `RagMilvusClient`：按 uri 自动判定 **Milvus Lite 文件模式** 或 **server 模式**；pymilvus 为可选依赖。
- **BM25 稀疏检索由 Milvus 内置 Function 完成**：建集合时声明 `FunctionType.BM25`（输入 text 字段，输出 sparse_vector），应用层不生成、不写 sparse 向量。
- 混合检索：`hybrid_search` 两个 AnnSearchRequest（dense + BM25），RRF 融合；支持 `group_by_field` 分组、ACL 过滤表达式（`acl IN [...]`）。
- 写入/读取：insert/upsert/delete_by_doc_id/delete_by_expr/get_chunks_by_ids；时间统一存 INT64 毫秒（UTC）；错误统一 `RagMilvusError`。
- **已接入重试**（core.retry）：`hybrid_search` / `get_chunks_by_ids` 在 **lite 模式**（本地 .db）不重试（`max_attempts=1`，本地失败多为确定性错误）；**server 模式**重试连接错误 / 服务不可用，退避延迟经 on_retry 埋点进 metrics（`retry.milvus.delay`）。

### 3.5 追踪（tracing.py）
- contextvars 轻量追踪：`trace_session(query_id)` / `current_trace()` / `TraceContext.add_span`。
- 新增 `register_span_observer` / `clear_span_observers`：span 记录时同步回调（observer 异常被吞），供 metrics 联动（`span.<name>` 计数）。
- 为未来 OpenTelemetry / Langfuse 接入预留（替换 add_span 内部实现即可，调用方 API 不变）。

### 3.6 重试（retry.py）
- `RetryPolicy`：**指数退避 + 均匀抖动 + retry_on 异常分类**；退避公式 `delay = min(base * factor^(attempt-1), max)`，再叠均匀抖动 `[-jitter*delay, +jitter*delay]` 防惊群；`from_settings` 从 `config.settings.RetrySettings` 构造。
- `retry_call`（函数级入口）/ `retryable`（装饰器工厂）；只在异常匹配 `retry_on` 时重试，其余立即原样抛出；耗尽 `max_attempts` 后原样抛最后一次异常（不包装）。
- 线程安全计数器 `retry_stats()`（total_attempts / total_failures / total_retries）与 `reset_retry_stats()`，供观测与测试。
- **已接入生产**：`LLMClient.chat`（瞬态异常自动重试，400 非瞬态不重试直接 json 降级）与 `RagMilvusClient.hybrid_search` / `get_chunks_by_ids`（lite 模式 max_attempts=1 不重试，server 模式重试连接错误/服务不可用）；退避延迟经 on_retry 埋点进 metrics（`retry.llm.delay` / `retry.milvus.delay`）。

### 3.7 性能指标（metrics.py）
- `MetricsRegistry` 进程级单例（`get_metrics`）：计数器 `incr` / 直方图 `observe`（毫秒）与 `timing` 上下文管理器 / `snapshot` 输出 `{count, sum, mean, min, max, p50, p95, p99}`；错误指标（名称以 `.errors` 结尾）额外输出 `error_rate`（错误计数 ÷ 同名基础指标计数）。
- **蓄水池抽样**：样本上限 `MAX_SAMPLES=10000`，样本满后以 MAX_SAMPLES/n 概率替换既有样本，任意时刻样本都是全量历史的无偏随机子集，内存占用恒定 O(MAX_SAMPLES)，分位数无偏。
- 脏标记 + 排序缓存：样本变更才重排，连续快照避免重复排序。
- numpy 可选加速（惰性探测缓存 `_NUMPY_AVAILABLE`，只探测一次）；缺失时纯 Python 最近秩线性插值兜底（与 numpy `method="linear"` 等价）。
- 线程安全。埋点：`graph.invoke` / `graph.invoke.errors` / `graph.fallback` / `retry.*.delay` / `span.<name>`（经 tracing observer）。

### 3.8 可观测性（observability.py）
- `setup_logging`：配置根 logger，Handler 格式化器自动附加 `[query_id]`（contextvar 读取，无绑定显示 `-`）；**幂等**，根 logger 已有外部 Handler 时不叠加。
- `get_logger`：返回 `rag4c.*` 命名空间的 logger。
- `bind_query_id` / `unbind_query_id` / `current_query_id`：contextvar 查询 ID 绑定（asyncio 并发互不串扰）。
- `init_otel`：**惰性**初始化，仅 `otel_endpoint` 非空时尝试 `import opentelemetry.*`；未配置 / 无依赖自动降级 no-op 返回 False；export 为占位 stub 不真正连网。
- `setup_observability` 一键入口 = setup_logging + init_otel + 注册 span observer（span 记录时同步进 metrics，key 为 `span.<name>`）。
- **`rag.answer_query` 装配时自动调用**（幂等），图路径与顺序回退路径均绑定 query_id。

### 3.9 图谱存储（graph_store.py）
- `RagGraphStore`：管理两张图专用集合——`rag4c_entities`（实体节点，schema `id` + `vector` + `text`，邻接信息入动态字段 `relation_ids` / `passage_ids`）与 `rag4c_relations`（关系边，动态字段 `entity_ids` / `passage_ids` / `subject` / `predicate` / `object`）。
- passage 角色由 `rag4c_chunks` 承担，图检索命中后按 chunk_id 回查文本，避免文本双写；pymilvus 为可选依赖（惰性导入）；所有 Milvus 调用错误统一包装 `RagGraphStoreError`。

### 3.10 运行 Registry（run_registry.py）
- `RunRegistrySink` 接收 streaming canonical `RunEvent`，在 sink fan-out 中 failure-silent；任何 Registry 异常都不得越过边界影响 QueryResult、cache、legacy SSE 或 typed SSE。
- 只保存 allowlisted、尺寸有界的 detached JSON。禁止 raw query/question/answer/response/text/prompt/ACL/tenant/dataset/document/chunk/embedding/vector/score/API key/authorization/bearer/cookie/token/异常 message/traceback/stack/path；单 event 最大 16 KiB，topology 最大 128 KiB。
- 内存状态机拥有 active/recent/slow/errors/cancelled/stuck 投影、node rollup、事件连续性/截断状态、容量/TTL 和同 worker 变更通知；不拥有 HTTP、SQLite schema 或问答执行。
- 默认上限：active 128、recent 512、每 run 1024 events、全局 32768 events、terminal TTL 21600 秒。query fingerprint 仅在配置专用 HMAC secret 时生成。

### 3.11 运行历史存储（run_history_store.py）
- 独立 `data/run-history.sqlite3`，stdlib `sqlite3` schema v1；表为 `schema_migrations/registry_meta/boots/workers/runs/run_events`，迁移记录含 schema shape checksum。
- 连接启用 `foreign_keys=ON`、`busy_timeout=1000`、WAL 与 `synchronous=NORMAL`。业务线程只做有界非阻塞 enqueue；单 writer 默认 queue 8192、batch 64、flush 100ms、shutdown grace 2000ms，locked/busy 使用 25/50/100/200/400ms 退避。
- heartbeat 默认 5 秒，30 秒 stale cutoff。旧 worker/boot 被标记 stale，其未终结 run 投影为 `interrupted`，不补造 canonical terminal。clean shutdown 同样只更新持久化投影。
- corrupt DB 会连同 `-wal/-shm` 旋转为 UTC 后缀并尝试重建；旋转/重建失败进入 memory-only。schema-too-new 为 read-only；schema drift/checksum/index 不符禁写并暴露健康原因，不在进程中 hot-switch 回持久化。
- retention 删除 terminal runs，默认 30 天或最多 100000 条；active 不直接删除，单事务最多 1000 条，不执行 VACUUM。级联删除 events；定期 checkpoint 而非无限增长。

**验证状态**：smoke_foundation / smoke_resilience 与 Route B pytest 覆盖（重试·指标·追踪 observer·Registry/SQLite/privacy/performance）；LSP 0 错误。

## 4. indexing/ —— 文档入库管线

**文件**：`hashing.py` / `chunker.py` / `chunker_recursive.py` / `chunker_qa.py` / `chunking_router.py` / `ingest.py` / `cleaner.py` / `strategies.py` / `contextual.py` / `graph_builder.py` / `triplet_extractor.py` / `parsers/`（base、registry、plugins、pdf_inspector、mineru_http、mineru_cli、docling_parser、tsr）

### 4.1 哈希（hashing.py）
- `text_hash(text)`：utf-8 字节 sha256 摘要（64 字符）。用于 Chunk.text_hash（内容校验/去重/stale 判断）与 chunk_id 确定性部分。

### 4.2 切分（chunker.py）
- `StructureAwareChunker`：结构感知切分。
  - 按 Markdown 标题（`#`~`######`）切章节，标题作为上下文拼在正文前；
  - 代码围栏、表格块**整体保留**（内部空行/标题不参与切分）；
  - 短章节（< min_chunk_chars）合并到前章，避免碎片；
  - 大章节（> max_chunk_chars）拆分子块（块级贪心 + 字符硬切 + overlap 重叠），同时生成**父块**（small-to-big 检索前置）；
  - 确定性 chunk_id：`{doc_id}::{seq:04d}::{sha256(text)[:12]}`，同输入必得同 id。
- `RecursiveChunker`（chunker_recursive.py）：递归固定切分（简单文档路径）——按分隔符优先级（段落 / 换行 / 句子 / 字符）递归降级，无父块，`chunk_mode="recursive"` 标记。
- `CsvQaChunker`（chunker_qa.py）：CSV / 表格 → 每行 QA 对（`text="问：…\n答：…"`），metadata 记录 row / headers / `chunk_level="qa"`；自动识别 Markdown 表格与纯 CSV 两种输入。
- `ChunkingRouter`（chunking_router.py）：切分路由——`chunking_mode=auto` 时按文档类型与复杂度决定：csv/excel → qa；短文本（≤ `simple_doc_max_chars`=4000 字且无版面组件）→ recursive；其余 → parent_child；也可显式指定 recursive / parent_child / qa。三模式 chunk_id 一致，模式切换不破坏幂等。

### 4.3 入库（ingest.py）
- `IngestPipeline`：`add_document` / `upsert_document`（先删旧再重建）/ `delete_document` / `ensure_collection`（幂等）。
- 串联：清洗 → 预切分 → 切分 → 批量嵌入 → 写 Milvus；失败统一包装 `IngestError`；在 trace_session 中自动记录 embed/insert span。

### 4.4 图索引（graph_builder.py）
- `GraphBuilder`（store + embedder + extractor）：对每个 chunk 调 `TripletExtractor` 抽取三元组 → 组装实体节点（`GraphEntity`）与关系边（`GraphRelation`）→ 批量嵌入 → 批量 upsert 到 `RagGraphStore`。
- **增量合并去重**：实体按名称大小写不敏感去重、关系按三元组文本去重；与库内已有节点按 text 精确匹配合并邻接，主键稳定（实体 = sha256(名称小写)、关系 = sha256(三元组文本小写)）。
- **级联删除**：删涉及 chunk 的关系，再删失去全部关系与 passage 引用的孤儿实体。
- `GraphBuildResult` 构建计数：chunk / triplet / entity / relation / failed_chunk。

### 4.5 三元组抽取（triplet_extractor.py）
- `TripletExtractor`（LLM，`llm.triplet` 槽位 temperature=0 保证确定性，模板 `prompts/graph_triplet_v1.txt`）；同 chunk 内三元组大小写不敏感去重，空字段丢弃，超长实体名截断到 64 字符。
- **失败不中断入库**：单 chunk JSON 解析失败（`ParseFallbackError`）仅跳过该 chunk（返回空列表）；底层 LLM 网络错误仍上抛（环境问题需显式暴露）。
- 确定性 `FakeTripletExtractor`：离线冒烟测试用（无需网络与模型）。

### 4.6 文档解析（parsers/）
- `DocumentParser` 接口 + `ParsedDocument` 契约 + `MineruParserError` + `create_parser` 工厂（按 `provider` 路由，函数体内惰性导入实现类）；完全离线可导入，副作用只发生在 `parse()` 内。
- `MineruHttpParser`：按 `api_key` 自动选链——**v4 精准解析**（需 Token，≤200MB / ≤200 页：上传 → 建任务 → 轮询 → 下载 Zip 解 Markdown）或 **v1 Agent 轻量链**（免 Token，≤10MB / ≤20 页）；httpx / requests 惰性导入，HTTP 错误码（含 429）统一包装 `MineruParserError`。
- `MineruCliParser`：subprocess 调本机 mineru CLI（npm 包 `mineru-open-api`），`flash-extract` 模式**免 Token**（≤10MB / ≤20 页）；输出 UTF-8 解码（errors="replace"），非零退出码 / 空输出 / 超时抛 `MineruParserError`。
- **插拔式引擎注册表**（registry.py + plugins.py）：「1 配置」统一入口——所有 vision 引擎同一形态接入（`ParserEngineSettings`：enabled / mode / priority 三字段同构）。
  - 注册：`register_parser_plugin(ParserPlugin(name, factory, describe))`（plugins.py 内置 mineru / docling，import 即注册、幂等）；新增引擎只需注册 + 加一段同构配置，选择逻辑**零改动**（auto 遍历已注册插件，按 priority 升序选第一个 enabled）。
  - 配置：`settings.parsers.engine`（auto / mineru / docling）、`parsers.mineru` / `parsers.docling`（同构三字段）、`parsers.plugins`（动态引擎配置字典，第三方引擎 import 时注入即可被发现）。
  - 开关：`enabled=false` 即「拔掉」该引擎（其重依赖绝不 import）；显式 engine 指定未启用引擎抛 `ParserPluginError`；全部禁用时 `create_vision_engine` 返回 None，`DocumentRouter.parse` 报可操作错误。
  - 免费 / 付费模式（mode 字段，引擎工厂自行解释）：mineru free=flash-extract / Agent 轻量（免 token），paid=extract / v4 精准（需 `RAG4C_MINERU_API_KEY`，缺 key 装配即报可操作错误）；docling local=本地 AI 模型免费（惰性 import，未装提示 `pip install docling`），api=云服务付费（预留，缺 `api_base`/`api_key` 报可操作错误）。
- `DoclingParser`（docling_parser.py）：IBM Docling 插件——local 模式惰性 import docling 重依赖，DocLayNet 布局类型映射到 DeepDoc 10 种版面组件；api 模式预留。

### 4.7 清洗 / 预切分 / 上下文增强（cleaner.py / strategies.py / contextual.py）
- `cleaner.py`：解析输出 → 切分之间的纯文本清洗关，固定顺序（去 URL → 去 Markdown 痕迹 → 去控制字符 → 去样板行 → 折叠空行），每步可独立开关、全部默认开启；确定性幂等（`clean(clean(x)) == clean(x)`），保留表格 / 代码围栏 / 标题结构。
- `strategies.py`：文档类型感知的分类型预切分（`parser -> cleaner -> strategy.chunk() -> StructureAwareChunker`），输出章节级 segment（非最终 chunk）；markdown 按标题分节 / pdf·word·txt 按段落分组 / excel 表格按块切分；未知类型回退段落分组。
- `contextual.py`：Contextual Retrieval（Anthropic how_to_enhance_your_rag 的 Indexing Enhancement）——为每个 chunk 生成文档级定位上下文；默认 `enabled=False` 零成本，失败静默降级不抛错。

**验证状态**：smoke_indexing PASSED（8 chunks）；图索引 / 三元组抽取由 smoke_graph（62 项）覆盖；LSP 0 错误。

## 5. retrieval/ —— 检索管线

**文件**：`rewrite.py` / `router.py` / `diversity.py` / `pipeline.py` / `sentence_window.py` / `query_enhance.py` / `graph_retriever.py`

### 5.1 查询改写（rewrite.py）
- `QueryRewriter.rewrite(query) -> (rewritten, changed)`。
- **复杂度门控**：查询 < 40 字符且不含疑问标记（？/如何/什么/为什么/是否 等）视为"具体明确"，跳过 LLM 调用（成本门）。
- 复杂查询调 LLM 改写（`prompts/query_rewrite_v1.txt`）；LLM 失败或结果为空时静默降级返回原文，**永不抛错**。

### 5.2 意图路由（router.py）
- `EmbeddingRouter`：查询与每路示例查询（exemplar）做余弦相似度，每路取最大；置信度 = `max(0, top1 - top2)` 夹到 [0,1]，低于阈值标记 degraded。
- `LlmRouterFallback`：LLM 分类兜底（`prompts/router_llm_v1.txt`），任何失败返回 `hybrid` 降级，不抛错。
- `RouteResolver`：组合两者——嵌入路由不降级直接返回；降级时尝试 LLM 兜底并取置信度更高者。

### 5.3 来源多样性（diversity.py）
- `mmr_select`：文档感知贪心 MMR（`score = λ·rel + (1-λ)·diversity`，同 doc 惩罚），纯 Python 确定性实现，无外部依赖。

### 5.4 管线编排（pipeline.py）
- `RetrievalPipeline.run(query, acl=None) -> RetrievalResult`，全程**不抛错**：
  1. 复杂度门控（+ 简单查询短路，跳过改写与路由）；
  2. 查询改写；3. 意图路由；4. 嵌入；
  5. 混合检索（候选放大到 `top_k*2`，group 参数透传，ACL 过滤）；
  6. **查询端增强**（开关开启且注入组件时）：HyDE（嵌入前用假设文档向量检索，BM25 文本仍用原查询）、子查询 / 后退问题分别检索并按 chunk_id 去重合并进候选；任一失败静默降级只记 trace，绝不中断；
  7. 来源多样性（group_mmr 时 MMR 后过滤）；
  8. **图谱分支**（见下）；
  9. 重排（失败保持原序并记 trace）；
  10. **检索端增强**：sentence_window_on 时命中子块回卷父块（small-to-big）；
  11. 裁剪 top_k。
- **图谱分支（已实现）**：路由命中 `vector_graph_rag` / `full` 且 `graph_retrieval_on` 开启、注入了图检索器时，执行图检索并取回 passage，与混合结果按 chunk_id 去重合并——`vector_graph_rag` 目标图结果**合并在前**（graph_first，branch="graph"），`full` 目标 hybrid 在前、图结果追加。以下六类情况降级 `degraded=True` 保留 hybrid：`graph_retrieval_on` 关闭 / 未注入检索器 / 图检索失败 / 无命中 / ACL 过滤后为空 / 与 hybrid 完全去重。
- 每阶段耗时写入 traces（`name:xx.xxms`）与全局 trace。

### 5.5 句子窗口（sentence_window.py）
- small-to-big 检索：命中子块（带 `parent_chunk_id`）时回取父 chunk 上下文；`replace=True`（默认）父块替换子块并继承 rank/score/branch，`replace=False` 父块追加在子块之后。
- 单层回取不级联（返回父块统一 `parent_chunk_id=None`）；milvus 以协议注入、模块导入零副作用；回取抛错 / 返回空 / 父块缺失时**静默降级**原样返回输入。

### 5.6 查询增强（query_enhance.py）
- 查询端增强组件（对齐官方 how_to_enhance_your_rag 的 Query Enhancement 方向，与 `hyde_on` / `subqueries_on` / `stepback_on` 开关对应）：
  - `HydeGenerator`（假设文档 hyde）：LLM 生成"假设文档"，以其向量做稠密检索；
  - `SubQueryGenerator`（子查询 subqueries）：复杂查询拆子查询分别检索后由管线合并；
  - `StepbackGenerator`（后退 stepback）：生成更抽象的后退问题补充检索。
- 增强结果并合进检索候选（按 chunk_id 去重）；LLM 失败一律静默降级不抛错（HyDE / Stepback 失败返回 None，SubQuery 失败返回 []，由管线回退原查询）。
- 索引端上下文增强（contextual）属 Indexing Enhancement，见 §4.7。

### 5.7 图检索（graph_retriever.py）
- `GraphRetriever`（store + embedder + llm 可选）：查询向量化 → 实体向量检索（`entity_top_k` / `entity_similarity_threshold`）→ 子图扩展（`expansion_degree` 跳，沿命中实体 `relation_ids`，每条扩展所得按跳距衰减得一个先验分 `expansion_prior_decay`）→ 关系向量检索（`relation_top_k` / `relation_similarity_threshold`）→ 合并候选按 id 去重并**按分数降序稳定排序**（检索命中用距离，扩展所得用先验分）→（`use_llm_rerank` 且注入 llm 时 LLM 从候选里**挑出**最多 `max_rerank_picks` 条，挑不满不算失败；返回的不是数组或调用失败才**静默降级**为按分数排序）→ 按"挑中的在前、其余按分数在后"收集 `passage_ids` 去重截断到 `final_top_k`。
- 阈值默认值是用 bge-m3 实测出来的，不是拍的：实体侧卡的是"整句查询 vs 名词短语"（正例 0.34~0.91），关系侧卡的是"整句查询 vs 三元组句子"（正例 0.62~0.80），两侧尺度不同，因此**不共用一个数**。依据见 `docs/审查报告与优化计划.md` §5.4。
- 存储层失败抛 `GraphRetrieverError`；检索**成功但无命中**不抛错，返回 `degraded=True` 空结果。

**验证状态**：smoke_retrieval **32 项全过**；增强 / 句子窗口由 smoke_enhance（29 项）覆盖；图检索由 smoke_graph（62 项）覆盖；LSP 0 错误。

## 7. verify/ —— 引用验证与弃权

**文件**：`claims.py` / `verifier.py` / `abstention.py`

### 7.1 声明切分（claims.py）
- `split_claims(answer)`：按中文句末标点（。！？；）与换行切分；< 4 字符碎片并入前条声明；确定性纯函数。

### 7.2 三层引用验证（verifier.py）
- `CitationVerifier.verify(answer, evidence) -> VerificationResult`，任何外部服务异常**捕获降级、不中断**：
  - **L1 存在性**：解析 `[N]` 编号映射到证据（按 chunk_id 去重后 1 基）；编号不存在 → `unsupported`。
  - **L2 文本哈希**：从 Milvus 取回最新 chunk 记录比对 `text_hash`；不一致 → `stale`（证据被修改/删除）。
  - **L3 蕴含判定**（成本分层）：judge 槽位按 `prompts/judge_groundedness_v1.txt` 逐条判定；支持 `strict` 全量 / `sample_ratio` 确定性抽样 / `entailment_mode="skip"` 跳过；LLM 失败降级 `exists_only`。
  - **事后引用指派**（任务书 6.3）：答案完全无引用标记时，用 BGE-M3 向量余弦相似度（≥ 0.5）把每条声明指派到最相似证据，再交 L3 把关——免费模型无法做生成期约束解码的平价替代。
  - `_clean_claim` 剥离声明中的 `[N]` 标记（验证与生成解析行为一致）。
- `VerificationResult`：citations / supported / missing_evidence / notes / entailment_scores。

### 7.3 双重阈值弃权（abstention.py）
- `AbstentionGate.decide(retrieval_scores, entailment_scores)`，短路判定：
  1. 无检索结果 → 弃权；2. 最高检索分 < 阈值 → "知识库无相关内容"；
  3. 蕴含分空或最高分 < 阈值 → "证据不足以支撑可靠声明"；4. 否则不弃权。
- **不使用 LLM 自我判断**，纯分数阈值，可离线验证。
- `calibrate_retrieval_threshold(unanswerable_scores, percentile=0.85)`：用评估集不可答样本的检索分数分位数校准阈值（numpy 可用时用 numpy.percentile，否则最近秩手动实现）。

**验证状态**：smoke_verify **25 项全过**（含 L1 越界/L2 stale/L3 映射/事后指派/L3 失败降级/弃权四决策/分位数校准）；LSP 0 错误。

## 10. rag/ —— 顶层编排

### 10.1 顶层编排（rag.py）
- `get_pipeline(settings=None) -> dict`：懒加载 + `@lru_cache(maxsize=1)` 进程级缓存，构造不联网、不加载模型（`import rag` 离线安全）。
- `answer_query(query, acl=None, retry=True, settings=None) -> QueryResult` 为 **dispatcher**：
  - `pipeline.graph_engine_on=True`（默认）时优先 `rag_graph.run_graph_answer`；图构建失败 / 图执行异常 / 未产出 final（返回 None）时回退 `_answer_sequential`（顺序编排），**两者行为完全一致**（同弃权门、同二轮检索、同 traces 语义、同 QueryResult 结构）；
  - 装配时调用 `setup_observability`（幂等）；回退路径也绑 query_id（`bind_query_id`），日志 / span 可串联；
  - 图不可用 / 异常记 `graph.fallback` 指标并打 exception 日志；
  - 二轮检索补救（`MAX_ROUNDS=2`，见 10.3）：首轮验证后若 `missing_evidence` 或 `not supported`，用原始查询重跑一次检索并合并证据，再生成+验证；无新增证据即停；
  - 双重弃权门：检索阶段（无结果/分数低于阈值）+ 验证阶段（蕴含分低于阈值）各判定一次；
  - **鲁棒性**：检索失败（Milvus 不可用）/ 生成失败 / 验证失败一律降级为弃权结果，不向调用方抛异常；
  - 结果含 citations / verdict(evidence_chunks) / route / traces（配合 core.tracing）。

### 10.2 图编排（rag_graph.py）
- LangGraph StateGraph：节点 `retrieve → abstain_retrieval → generate_verify →（retrieve_again 环）→ abstain_final → finalize`，条件边实现二轮检索环与弃权短路；节点返回 dict 做状态增量更新（纯函数风格，便于单测）。
- **业务失败**（检索抛异常 / 弃权门命中）一律产出弃权 QueryResult 存入 `state["final"]` 后经条件边短路到 END，**不向图外抛错**。
- 节点**未捕获**的异常由 `run_graph_answer` 统一捕获：记 `graph.invoke.errors` 指标 + exception 日志并返回 None，触发 `rag.answer_query` 回退顺序编排——绝不向调用方抛异常。
- **编译图按组件缓存**（按 `id(comp)`，同一进程内 comp 不变则复用，避免每次查询重建图；CompiledStateGraph 可重入，多线程并发 invoke 互不串扰）。
- langgraph **惰性导入**：未安装时模块仍可离线 import（仅 `build_graph` / `run_graph_answer` 返回 None）；共享纯函数从 `rag_common` 导入，不 import `rag`（避免跨模块私有耦合）。

### 10.3 共享编排工具（rag_common.py）
- `MAX_ROUNDS`（=2，1 轮 + 1 轮补救）、`generate_and_verify`（一轮生成 + 三层验证，失败按弃权处理）、`merge_chunks`（按 chunk_id 合并多轮结果，保持首次出现顺序）、`evidence_chunks`（检索结果转 eval 裁判用的证据 dict 列表）。
- rag 与 rag_graph 两条编排路径共用，消除跨模块私有耦合；本模块不 import `rag` / `rag_graph`。

**验证状态**：`import rag` OK；`get_pipeline().keys()` = `['retrieval','generator','verifier','gate','settings']`；图编排 / 回退集成由 smoke_resilience（80 项，含图/顺序一致性差分）与 smoke_graph（62 项）覆盖；LSP 0 错误；经 `--dry-run` 全链路走通。

## 桥服务企业级加固（2026-08 已完成）

桥服务（server/app.py）已按企业级标准加固：

- **错误契约**：全部异常统一 JSON `{"error": {"code", "message"}}`（含 404/422/500），前端按 code 分支处理；
- **并发与超时**：查询与 SSE 共用有界执行器；每进程执行并发 4 + 排队上限 20（超出 429）+ 排队/执行统一 240s deadline；HTTP 超时后同步 worker 继续占槽到真实结束；
- **查询缓存**：tenant+query+排序 ACL+retry 相同则命中 10 分钟 TTL LRU（容量 64），并发 miss 使用 single-flight；
- **SSE 流式问答**（/api/query/stream）：使用共享执行器和容量 256 的背压队列，不再每流创建 daemon thread；阶段事件 + 逐 token 推送，见 rag_stream.py；
- **深度健康探活**（server/health.py）：ok/degraded/down 三级状态 + Milvus 只读探活（集合/行数）+ LLM 槽位配置完整性 + 熔断器联动；5s 快照缓存与 single-flight，刷新时可返回旧快照；
- **入库并发**（server/documents.py）：每进程有界执行器并发 2 + 队列 8（满载 429），同 doc 活动任务重复提交 409，Pipeline 按 worker 线程复用；
- **熔断器**（core/circuit.py）：retrieval / llm.generation 独立熔断（连续失败 3 次打开、30s 冷却、半开探测），编排层快速弃权，开合事件进指标与健康状态；
- **评测互斥**（忙时 409）+ eval 结果与 .env 原子写入（临时文件 + os.replace + 写锁）；
- **可观测性**：请求访问日志（慢请求 >10s 告警）+ 指标周期持久化（data/metrics-history.jsonl，60s 粒度，5MB 轮转）+ /api/metrics/history + /api/metrics/prometheus。

通知 receipt 的持久 `target_route_code + target_route_params_json` 通过 `core/notification_route_adapters.py` 转成安全 UI route。实现复用 `core.providers.ProviderRegistry`；quality alert / approval 各自保留字段白名单、租户与 source id 一致性校验。未知组合 fail-closed；宿主限制 adapter path 为 `/enterprise/...`、验证 query，并自行生成 href，不信任策略的 href。Adapter 注册不开放 source kind 数据库 CHECK，也不改变通知物化与 handoff；新增可导航类型还需同步前端 allowlist。交接文档：`docs/2026-09-23-notification-route-adapters.md`。


### Index worker revision strategy（2026-09-23）

`IndexOperationWorker` 的 revision 更新由 `core/projection_revision_strategies.py` 按 target store 注册。MILVUS 和 graph 保持原 revision 条件；未知/non-canonical target policy 在 handler 前 fail/retry；revision callback 在 handler 前 pin，要求同步执行。此注册点不包含 primary/secondary attempt 生命周期及 durable deletion target list。详见 `docs/2026-09-23-projection-worker-revision-strategy.md`。
