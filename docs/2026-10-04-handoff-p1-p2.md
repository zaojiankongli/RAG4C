  已误拒 4 条可答。提到 0.85 附近：幻觉 → 0.091，过度拒答 0.033 → 0.171。

### F3.1 端到端延迟拆解（`3b151ee`）

## 二、已完成但是负结果（假设被证伪）

计划明确写了「假设被证伪也是有效结果」。三条：

### F2.1 BM25 分析器（`eae613c`）

评测集合上重建为 chinese analyzer，**全部指标逐位不变**（delta 全 0.0000，
26 条里只有 1 条结果变化且 NDCG 未变）。排除了"改了没生效"：schema 确认生效、
BM25 稀疏检索中文查询能召回、结果确实变了。

口径：这套语料是中英混排的仓库文档，standard 按空白切词本来就切得对。
**纯中文语料上 BM25 失效**这件事由 `config/settings.py` 注释的实测单独证实。

### F2.3 候选宽度（`ff3cf95`）

候选 30 → 40：整体 ndcg 0.8024 → 0.8021，en +0.001 / zh −0.003，
recall@10 只动 0.0008。**"gold 就排第 2 位"不是候选池太窄**——gold 本来就在
候选里、reranker 已经看过，是它给的排序把它放在第 2。问题在**重排器的判别边界**。

### F2.2 路由决策（`f477e3e`）

`full` 与 `vector_graph_rag` 都走 `GraphStage`，而它
`requires_flag = "graph_retrieval_on"`，实测该开关与 `graph_index_on`
**都是 False** → **82 条（56.5%）走图谱路由的查询实际检索行为与 hybrid
完全相同**。所以改默认路由的收益不是"小"而是**恒为零**。

**决策：维持默认。** 真正的决策被推后到 F5（要不要开图谱）。

| 来源 | 场景 | 最大头 | 占比 | 适用条件 |

## 四、修掉的静默失效型 bug

| 缺陷 | 后果 |
|---|---|
| **槽位温度被 .env 重置为 0.2**（`742e76f`） | `.env` 里只要提到某槽位（哪怕只写 model），pydantic 重建对象，generation 0.7→0.2、judge 0.0→0.2。judge 温度非零让幻觉率不可复现，**直接威胁 F1.2 基线的可比性** |
| **`--gold` 从未被消费**（`eae613c`） | `--corpus milvus` 隐式强制 PRODUCTION_GOLD。**在此之前所有标注为 `--gold production` 的实验其实都跑的是 docs 标注** |
| **重建脚本导出字段写死**（`eae613c`） | 漏了 `document_revision`/`content_revision` → 回填整批被拒，**而集合已被 drop** |
| **`--collection` 没改 settings**（`eae613c`） | 评测集合被 drop，新集合建在**生产名字**上 |
| **`--restore-from` 语义是"追加"**（`eae613c`） | analyzer 不变 + 旧行还在 → 实测 454 行（227×2） |
| **门禁 `--help` 抛 ValueError**（`6094111`） | help 串里的字面量 `%` 被 argparse 当格式符。**整个脚本连参数说明都打不出来** |

共同特征：**不报错、只让读数失去意义**。这也是本仓反复出现的故障类型
（见 `.workbuddy/memory/MEMORY.md`）。

## 八、追记：F1.2 基线出来之后（本文档上半部分写于基线完成前）

`eval/baseline.json` 已产出（145 条，2 小时 3 分），完整结论见
`docs/2026-10-04-f12-answer-baseline.md`。三个必须知道的数字：

| 指标 | 值 | 门禁 |
|---|---|---|
| **幻觉率** | **0.6364** | FAIL（阈值 0.10，超 6.4 倍） |
| 平均有据性 | 0.8298 | PASS |
| 降级率 | 0.1034 | FAIL |

**最重要的发现：有据性识别不出幻觉。** 14 条幻觉样本里 11 条（79%）的
`relevance` 恰好 0.00，而 `groundedness` 在 0.71~1.00——**不是编造，是答非所问**。
`avg_groundedness = 0.83` 完全掩盖了 0.636 的幻觉率，两者正交。

**根因**：`verify/verifier.py:559` 构造 L3 提示词时只替换 `{claims}` 与
`{evidence}`，模板 `prompts/judge_groundedness_v1.txt` 里也没有 `{question}`
占位符——**L3 在原理上不可能判定「证据是否回答了用户的问题」**。
诊断与提案见 `docs/2026-10-04-abstention-misses-off-topic-answers.md`。

**F1.5 验收通过**：把 `avg_groundedness` 门槛从 0.60 提到 0.95，门禁如期变红
（`docs/2026-10-04-f15-gate-acceptance.md`）。

**降级率根因未定位**：两个假设（3 并发限流、输入规模特殊）都已证伪，
详见诊断文档第五节。下一步是给 L3 失败路径补诊断信息再跑一轮（纯可观测性、
不改行为，不需要确认）。
