## 结论

**幻觉率 0.6364 → 0.0000，降级率 0.1034 → 0.0207——门禁六项全部 PASS。**

| 指标 | v1 | **v3** | delta | 门禁 | 判定 |
|---|---|---|---|---|---|
| **幻觉率** | 0.6364 | **0.0000** | -0.6364 | ≤ 0.10 | **PASS** |
| **降级率** | 0.1034 | **0.0207** | -0.0828 | ≤ 0.05 | **PASS** |
| 过度拒答率 | 0.0407 | 0.1870 | +0.1463 | ≤ 0.30 | PASS |
| 平均有据性 | 0.8298 | 0.8501 | **+0.0204** | ≥ 0.60 | PASS |
| 平均相关性 | 0.8225 | 0.9571 | **+0.1346** | ≥ 0.60 | PASS |
| 引用失败率 | 0.2471 | 0.1596 | -0.0876 | ≤ 0.25 | PASS |
| 拒答率 | 0.0897 | 0.3103 | +0.2207 | — | 设计意图 |

**七项里五项改善、一项（拒答率）按设计上升。** 门禁判定里 `passed` 仍为
false，只因劣化带报出了拒答率/过度拒答率的上升——那正是改动的设计意图。

## 三轮基线的演进

| | v1 | v2（重试 2 次） | v3（重试 4 次） |
|---|---|---|---|
| 幻觉率 | 0.6364 | 0.0909 | **0.0000** |
| 降级率 | 0.1034 | 0.1034 | **0.0207** |
| 过度拒答率 | 0.0407 | 0.1138 | 0.1870 |
| 平均有据性 | 0.8298 | 0.8153 | 0.8501 |
| 降级分类 | judge_failed 9 / entailment 9 | entailment 13 / judge 6 | **entailment 2 / judge 1** |

**v2 → v3 只改了一件事：JSON 解析重试次数 2 → 4。** 效果是
`entailment_unavailable` 从 13 降到 2、`judge_failed` 从 6 降到 1，
降级率 0.1034 → 0.0207。

这也回答了「过度拒答为什么从 0.1138 涨到 0.1870」：**降级的那 15 条里，
相当一部分其实是有答案的**（v2 里它们因裁判失败被判 0.75~0.83 幻觉，
v3 里裁判成功了、正常作答）。修好裁判之后，真实的 `topic_only` 判定才浮出来。

## 过度拒答的 23 条是什么

**不是故障**——`degraded_kinds` 为空、notes 写的是
`弃权: 证据主题相关但不包含所问事实`。是 v2 模板判它们 `topic_only`。

它们的检索分与正常作答的可答**高度重叠**：

| | p10 | p50 | p90 |
|---|---|---|---|
| 被 `topic_only` 拦的 23 条 | 0.238 | 0.937 | 0.997 |
| 正常作答的可答 | 0.745 | 0.979 | — |

p50 只差 0.04——**检索层完全分不开它们**。这再次印证 F1.3 的结论：调阈值
解决不了（p50 阈值就要拒 49.5% 的可答），只有"证据是否回答了问题"这一维
能判。而这正是 v2 做的。

代价的性质是清楚的：**用 23 条过度拒答换 22 条幻觉清零**。门禁给过度拒答
留的余量（0.30）正是为这种情况准备的。

## 三处改动

1. **`7f7cc3d`** — `prompts/judge_answer_relevance_v2.txt`：加 `{question}`
   与 `answer_status ∈ {answered, topic_only, irrelevant}`。
   **生产用 v2、评测仍用 v1**（基线按 v1 测，换模板就失去可比性）。
2. **`209c36e`** — 弃权门**独立判定** `answer_status`。最关键的实现坑：
   门对逐条蕴含分数取 `max`，而幻觉样本的形态是「4 条 supported + 整段
   答非所问」，混进逐条分数里 max 仍是 1.0、拦不住。
3. **`3bcf66d`** — `json_parse_retries` 可配（降级率根因是
   `judge_parse_failed`）。v3 用 4 次验证有效。

## 测试

新增 6 个测试文件、约 60 条测试，全部做过变异验证：

| 变异 | 结果 |
|---|---|
| `answered` 也压分 | ✅ 被抓 |
| 缺 `answer_status` 默认为 `answered` | ✅ **第一版没抓到**（answered 与 `""` 对分数效果相同），补断言后抓到 |
| `topic_only` 标成 `unsupported` | ✅ **第一版断言写成"两者不等"，误标后恰好相等所以不变红**；改白名单后抓到 |
| 门的检查顺序错误 | ✅ 被抓（2 条） |
| 空 `answer_status` 也拒答 | ✅ 被抓（2 条） |
| 重试边界写死 `attempt == 1` | ✅ 被抓 |

修复了一个真实回归：`verify` 加 `question` 形参打断了 **11 处**按旧签名
实现的测试桩，症状离病因隔三层（TypeError 被编排层当"验证失败"吞掉，
显示为"事件序列不对"）。已加契约测试钉住"新形参必须有默认值"。

## 五条方法论教训

1. **判据也会把成功的信号当成失败信号**。第一版验收把「平均相关性 +0.111」
   判成"门被关死"，而那正是生效的证据（幻觉样本的 0.00 拉低了 v1 均值）。
   验收工具自己必须有测试。
2. **测试断言两侧行为等价时恒真**。两个变异第一版都没抓到。
3. **契约变更的漏网桩在别的测试文件里**，要用 Grep 扫全量而不是只跑改动
   直接触及的文件。
4. **三次经验性猜测连续落空时，停止猜测、去拿能直接回答问题的数据**。降级率的
   并发 / 输入规模 / 声明数三个假设都证伪后，正确做法是补诊断字段再跑一轮。
5. **分析工具存在的意义就是防止人对着原始数据手算**。手工重算阈值时用了高分侧
   分位数，算出"能拦 2/2 幻觉"——实际会拒掉 85% 的可答问题。
