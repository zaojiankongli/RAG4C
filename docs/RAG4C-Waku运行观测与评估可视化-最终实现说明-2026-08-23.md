## 2. 为什么参考 Waku，但没有照搬 Waku

Waku 最有价值的不是某个 CSS 风格或某张图，而是下面这套原则：

> 后端产生一份稳定、可关联、可重放的运行事实；实时图、历史、慢请求、错误分析和评估页面只是这份事实的不同投影。

RAG4C 改造前存在三套容易漂移的“流程真相”：

- `rag_stream.py` / `rag_graph.py` 中真正执行的流程；
- SSE 只暴露的粗粒度 `phase/token/done/error`；
- 前端固定节点和中文 traces 正则推断。

如果直接把 LangGraph 图拿来画，会产生新的错误，因为 RAG4C 默认流式问答并不走 LangGraph。最终选择是：

- 保留 RAG4C 的顺序流式主路径；
- 由独立、引擎无关的 semantic topology 描述流程；
- 由 request-scoped events 表达真正的运行状态；
- LangGraph 留到第二批通过 adapter 映射，不成为唯一引擎。

Waku 的精髓被迁移成了以下架构分层：

```text
Topology Definition
        │
        ├── 稳定节点、边、插件能力和配置快照
        ▼
Canonical Run Facts
        │
        ├── start / complete / failure / skip / retry / route / terminal
        ▼
Frontend Projections
        ├── QueryPage 紧凑阶段
        ├── VisualizePage 完整流程驾驶舱
        ├── MonitorPage 指标与保护信号
        └── EvalPage 质量评估和失败用例诊断
```

参考研究证据：

- `.planning/2026-08-22-qa-flow-visualization/findings.md`
- `docs/superpowers/specs/2026-08-22-run-observability-fact-layer.md`
- Waku 仓库：`https://github.com/ShenSeanChen/Waku-agent`

## 5. Canonical RunEvent 协议

核心实现：`core/run_events.py`

### 5.1 信封字段

| 字段 | 说明 |
|---|---|
| `schema_version` | 当前固定为 1 |
| `run_id` | 后端为每次请求生成的唯一 ID |
| `seq` | 单个 run 内从 1 开始严格递增 |
| `occurred_at` | 带时区 UTC 时间 |
| `elapsed_ms` | 使用 monotonic clock 的运行累计耗时 |
| `topology_id` | 语义拓扑类型，如 `rag.query` |
| `topology_revision` | 当前有效配置和插件组合的 canonical hash |
| `type` | 事件类型 |
| `node_id` | 节点 ID，可选 |
| `attempt` | 执行轮次，可选 |
| `duration_ms` | 节点耗时，可选 |
| `attributes` | 有界 JSON 元数据 |
| `error` | 结构化低基数错误信息 |

### 5.2 事件类型

运行：

- `run.started`
- `run.completed`
- `run.failed`
- `run.cancelled`

节点：

- `node.started`
- `node.completed`
- `node.failed`
- `node.skipped`
- `node.cancelled`

控制与降级：

- `route.selected`
- `retry.started`
- `retry.completed`
- `retry.failed`
- `retry.skipped`
- `degraded`

### 5.3 生命周期不变量

- `run.started` 必须是 `seq=1`。
- seq 在单 run 内无重复、无倒退。
- node 必须先 started，才能 completed/failed/cancelled。
- skipped 节点不能先 started。
- 非 repeatable 节点只允许 attempt 1。
- repeatable attempt 必须连续。
- terminal 只能出现一次并且必须是最后一个 canonical event。
- terminal 后所有事件被拒绝。
- sink 异常被吞掉，不改变业务控制流。
- sequencer 使用锁保护并发状态。

### 5.4 不可变性

事件模型是 frozen Pydantic v2 模型，同时对嵌套 attributes 做深度复制和冻结：

- 修改调用方原始 dict/list 不会改变已发布事件；
- 从 MemoryRunEventSink 读取的嵌套数据不能修改；
- `run_event_dict()` 会返回普通、独立、可 JSON 序列化的 dict/list。

## 6. 不可变语义拓扑

核心实现：`rag_topology.py`

### 6.1 核心模型

- `TopologyNode`
- `TopologyEdge`
- `RagTopology`
- `TopologyContext`
- `TopologyFragment`
- `RagTopologyPlugin`

### 6.2 核心节点

```text
receive
complexity_gate
rewrite
route
embed
search
diversity
gate.retrieval
generate
verify
gate.final
finalize
```

可选组件节点：

```text
plugin.hyde.expand
plugin.subqueries.expand
plugin.stepback.expand
graph.retrieve
rerank
sentence_window
```

### 6.3 enabled 与 available

- enabled：配置要求启用。
- available：组件实际已装配。
- 配置启用但组件不可用时，节点仍保留在拓扑中并标记 unavailable，运行期再发 skipped/degraded。

### 6.4 revision

- 节点和边按稳定 ID 排序。
- canonical JSON 使用固定序列化规则。
- revision 是 SHA-256 截断值。
- 插件登记顺序不会改变导出 topology 和 revision。

### 6.5 cache replay

缓存回放使用独立拓扑：`rag.cache_replay`。

它不会伪装成重新执行检索、生成和核验。每个缓存请求仍创建新的 run ID，不能复用 cache owner 的 run ID 或 seq。

## 8. 检索管线插桩

文件：`retrieval/pipeline.py`

覆盖节点：

- complexity gate；
- rewrite；
- route；
- HyDE；
- embedding；
- hybrid/dense search；
- SubQueries；
- Stepback；
- diversity；
- graph retrieval；
- rerank；
- Sentence Window；
- dataset scope；
- truncate。

语义规则：

- disabled/unavailable：`node.skipped`。
- 可恢复失败：`node.failed(recoverable=True)` + `degraded`。
- 致命错误：记录 failed 后继续原样抛出。
- 图检索失败明确记录 requested route 和 effective hybrid route。

并行规则：

- HyDE、SubQueries、Stepback 工作线程不能直接写 sequencer。
- 父线程提交任务时立即发 `node.started`。
- 父线程接收 Future 结果后发 completed/failed。
- 这样既能显示并行 active 状态，也不会破坏 seq。

## 10. HTTP 边界、缓存和并发

文件：`server/app.py`

### 10.1 请求级 run

每个 `POST /api/query/stream` 请求在 L1 lookup 之前创建 `_HttpStreamRun`：

- 新 run ID；
- normal/cache replay topology；
- sequencer；
- SSE sink；
- exactly-once terminal guard。

### 10.2 缓存

支持：

- L1 进程内缓存；
- L2 Redis；
- same-process single-flight；
- cross-process lock/single-flight；
- 语料 epoch；
- 弃权结果短 TTL。

关键安全规则：

- 缓存 payload 不含 run ID、seq 或 topology。
- 每次 replay 创建新 run。
- `done` 交付并恢复后才写缓存和 completed 计数。
- 客户端收到 done 后立即关闭、未消费响应或中途取消时不写缓存。

### 10.3 Queue 和 slot

- queue 满：HTTP 429 + rejected fact。
- slot wait timeout：HTTP 503 + timeout fact。
- 正常 owner 获取执行槽后进入 RAG。
- cleanup 负责 pending、flight 和锁释放。

### 10.4 新指标

| 指标 | 定义 |
|---|---|
| `query.requests` | 进入流式 HTTP endpoint |
| `query.completed` | 成功交付 answered/abstained 响应，包括缓存回放 |
| `query.errors` | 未形成 QueryResponse 的内部错误 |
| `query.abstained` | 已交付的弃权结果 |
| `query.cache_hits` | L1/L2 直接命中 |
| `query.singleflight_joined` | 加入已有计算 |
| `query.rejected` | 队列满/主动拒绝 |
| `query.cancelled` | 用户取消或响应未消费 |
| `query.timeouts` | queue/single-flight/stream deadline 超时 |

旧 `query.total` 保留为“实际执行问答管线并成功完成的计算耗时直方图”。

Monitor 弃权率使用：

```text
query.abstained / query.completed
```

因此缓存弃权不会把比例推到 100% 以上。旧后端没有 `query.completed` 时才回退 `query.total` 或 recent queries。

- 提问开始时先生成 provisional ID。
- 收到 `run.started` 后替换为 backend run ID。
- 保存 topology ID/revision 和完整节点/边。

### 12.2 typed 守卫

拒绝：

- 其他 run ID；
- topology 变化；
- seq 重复、倒退或缺口；
- terminal 后事件。

### 12.3 三种投影来源

- `typed-events`：后端权威拓扑，UI 标签“后端拓扑”。
- `coarse-phase`：旧后端实时阶段兼容图。
- `trace-inferred`：历史 trace 推断，边标为 inferred。

### 12.4 desync

收到 `run_event_desync` 或 seq gap：

- run 标记为 desynchronized；
- 显示警告；
- 停止接受后续 typed facts；
- legacy done、REST fallback 或用户取消仍可本地收敛终态；
- 不把缺失 typed history 当作完整事实。

### 12.5 本地终态 fallback

- typed terminal 已到达：本地 complete/cancel 不能覆盖。
- typed terminal 未到达：REST 成功可本地完成，用户停止可本地取消。
- abstained fallback 会把 output 节点标为 degraded。

### 12.6 安全详情

前端只展示：

- normalized reason code；
- route；
- error code/category；
- recoverable；
- attempt/duration。

reason 必须匹配小写 ASCII code 格式且不超过 64 字符。完整 error message 和任意 attributes 不进入 inspector。

### 21.3 访问控制与隐私

- IPv4/IPv6 loopback 默认允许，不信任 `X-Forwarded-For`。远程未配置 operator token 返回 403；配置后缺失/错误 Bearer 返回 401 + `WWW-Authenticate: Bearer`，比较使用 constant-time digest。
- 远程必须提供 `X-RAG4C-Tenant`；header 与 `tenant_id` query 不一致返回 400。每个请求只解析一个 scope；未知 run 与跨 scope run 返回完全相同的 `run_not_found` 404。
- public OpenAPI 不含 `tenant_scope`、`ops_bearer_token`、`fingerprint_secret`。query fingerprint 只在专用 HMAC secret 已配置时出现。
- Registry/API 只允许 canonical envelope、受限 event attributes、冻结 topology、node rollup、枚举/计数/耗时/reason code。禁止 raw query/question/answer/response/text/prompt/token/API key/authorization/cookie/ACL/tenant/dataset/document/chunk/embedding/vector/score/完整异常 message/traceback/stack/path。
- 单 event JSON 最大 16 KiB，topology 最大 128 KiB；嵌套深度、数组/对象大小、字符串长度和 finite/non-negative 数值均有防御性校验。

### 21.4 schema v1、WAL、恢复与保留

- 独立数据库 `data/run-history.sqlite3`；表为 `schema_migrations`、`registry_meta`、`boots`、`workers`、`runs`、`run_events`，并验证迁移 checksum、表/index shape。
- 连接启用 `foreign_keys=ON`、`busy_timeout=1000`、`journal_mode=WAL`、`synchronous=NORMAL`。业务线程只做有界非阻塞 enqueue，不进行 SQLite I/O，也不等待 queue 腾位。
- writer 默认 batch 64/flush 100ms；locked/busy 退避 25/50/100/200/400ms。queue full、disk full、locked、unwritable、read fault 都降级并暴露 health，问答继续。
- heartbeat 5 秒、stale cutoff 30 秒。重启发现旧 worker/boot stale 时，将旧 running 持久化投影标记 `interrupted`；不补造 canonical terminal。clean shutdown 也只更新存储投影。
- corrupt DB、`-wal`、`-shm` 旋转为 UTC `.corrupt-*` 后尝试重建；失败进入 memory-only。schema-too-new 为 read-only；schema drift/checksum/index 不符禁写。boot 内不 hot-switch 回持久化。
- retention 只删除 terminal runs：默认 30 天或最多 100000 条，active 不直接删除；单事务最多 1000 条并级联 events，不宣称永久保留，也不执行 VACUUM。

### 21.5 API、cursor 与 long-poll

| API | 契约 |
|---|---|
| `GET /api/runs/health` | Registry/memory/persistence/WAL/writer/heartbeat/retention 与 `scope_stability`；disabled/degraded 明示 |
| `GET /api/runs` | `recent/active/slow/errors/stuck`；重复 status、slow_ms、带时区时间、可选 fingerprint；limit 默认 50/最大 100 |
| `GET /api/runs/{run_id}` | summary、冻结 topology、node rollup、history integrity/persistence |
| `GET /api/runs/{run_id}/events` | `after_seq`，limit 默认 200/最大 500，wait 默认 0/最大 25000ms，返回 terminal/timed_out/history_state/earliest seq |

list cursor 是 canonical base64url + HMAC-SHA256 的 v1 keyset cursor，排序固定为 `started_at DESC, run_id DESC`；首屏冻结 `as_of`，后续页绑定 scope、filter hash 与 3600 秒 TTL。400 代码区分 `cursor_invalid`、`cursor_expired`、`cursor_scope_mismatch`、`cursor_filter_mismatch`；无时区边界为 422。

long-poll 不占用 query executor。same-worker 等 Registry 通知，cross-worker 以 250ms durable watermark 轮询；并发最多 64，超限 429 + `Retry-After: 1`。无法补齐的 seq gap 返回 409 `run_event_gap` 和 earliest/latest；读路径不可用返回 safe 503。

### 21.6 前端 source precedence、tabs、banners 与 Monitor

- 当前选中的 live run：typed-event projection 优先；typed 不可用时用既有 coarse phase/trace，保证旧后端可用。其他选中 run 使用 server-history topology/events。
- 同 run 本地 raw-event buffer 立即显示；server pages 补缺且不覆盖已有 live seq。只有 server seq 从 1 连续到 reported latest 时才 authoritative。不同 run 永不合并，raw buffer 不落盘、不进 localStorage。
- 终态 1000 events 默认以 200 条页连续 catch-up；活动 run 使用 25000ms long-poll。409 从 `earliest_available_seq - 1` 恢复并保持 history gap；已知 run 后续 404 表示 retention expired，不切 demo。
- Visualize 四 tab：`process`、`timeline`、`events`、`knowledge`；URL 独立保存 `run/node/tab/view/follow`。timeline 是可访问 DOM + 表格等价视图；events 只挂载当前页并复制已脱敏 JSON；Knowledge 缺字段显示未记录，不按 0 推断。
- banners 分开表达 disabled、unauthorized、legacy、unavailable、Registry degraded、reconnecting、live transport desync、partial history、memory-only、partial/unavailable persistence、retention expired。
- Monitor 并行查询 active/stuck/slow/errors/cancelled，稳定 `run_id` 深链到 timeline/events。health 404 才进入 legacy recent-query；network/5xx 保留最后真实数据并显示 stale/reconnecting；disabled/401/403/404 是永久 capability transition。没有 demo history substitution。

## 25. 总结

第一批运行事实层现在已经由 Route B 提升为受保护、可查询、可恢复且有界的运行历史：内存 Registry 保持 canonical 事实，异步 SQLite WAL 提供 durable history，Ops API 提供 tenant-safe cursor/long-poll，前端以明确 source precedence 展示流程、时间线、事件和 Knowledge，并对 legacy、memory-only、gap、reconnect、retention 状态诚实降级。

RAG4C 仍保留顺序流式、插拔式检索、三层引用核验、二轮证据补救、弃权和缓存语义；Registry 是旁路观测与排障基础，不是新的执行引擎，也不扩大 raw data 收集范围。
