## 1. 调研：为什么"视觉质量"一直无法验收

用户验收标准里写着"前端视觉质量显著提升"。但在此之前，这个项目**没有任何能证明
它的东西**——只有 36 张 PNG。PNG 不能进 CI、不能比较、不能给出"这轮比上轮好在哪"，
于是"提升"只能靠自我评价。R5 的第一件事不是改样式，而是**把"好不好看"拆成可复现的数字**。

### 1.1 第一个发现：此前的视觉证据全是无效的（P0）

写度量脚本时顺手查了页面上必然出现的东西，先撞上 `button.px-5.py-2`（文案"下一步"）
出现在**每一页**的对比度与触控目标清单里——它是新手引导弹窗里的按钮。
根因：

```js
// frontend/src/OnboardingTour.tsx
const STORAGE_KEY = "rag4c.onboarding_done";
// 引导根节点是一层 fixed inset-0 z-[9999] 的全屏遮罩
```

而 `frontend/scripts/shoot.mjs` 只设置了主题：

```js
await ctx.addInitScript((t) => { window.localStorage.setItem("rag4c.theme", t); }, theme);
```

**没有置 `rag4c.onboarding_done`，所以那层全屏遮罩一直开着——36/36 张截图拍到的都是
引导弹窗，不是页面本身。** 这解释了为什么下面那个"白底白字"的严重缺陷能活到今天：
**真实页面从来没有进过视觉评审**。

**已修**：`shoot.mjs` 与新的度量脚本都在 init script 里置 `rag4c.onboarding_done = "1"`。

### 1.2 第二个发现：侧栏主导航基本不可见（P0，已修）

度量出来的最高频对比度违规是 `span.t-menu__content`，ratio = **1.15**。
逐层取计算样式后根因确定：

| 元素 | backgroundColor | 说明 |
|---|---|---|
| `aside.app-sider` | `rgb(15, 21, 35)` + 墨蓝渐变 | 侧栏被改造成深色墨轨 |
| `div.t-default-menu` | **`rgb(255, 255, 255)`** | TDesign 外层容器自带白底，**没被覆盖** |
| `span.t-menu__content` | `rgba(226, 232, 250, 0.68)` | 菜单文字取的是近白 `--sider-text` |

→ **白底压近白字**。项目里已有 `.app-sider .t-menu { background: transparent }`，
但漏了它外面那层 `.t-default-menu`。

**已修**（`frontend/src/styles.css`）：让 `.app-sider .t-default-menu` /
`.t-default-menu__inner` / `.t-menu--scroll` 透明，露出 aside 的墨蓝。
复验：`div.t-default-menu` 的 computed background 由 `rgb(255,255,255)` 变为
`rgba(0, 0, 0, 0)`，有效背景回落到 `rgb(15, 21, 35)`。

### 1.3 第三个发现：fallback 组件把框架私有 props 透传到 DOM（P1，已修）

`node scripts/shoot.mjs` 在 2 主题 × 3 视口的**每一张**截图都报同一条 React 警告：

```
Warning: Received `true` for a non-boolean attribute `code`.
   at span ...
```

根因在兼容层 `frontend/src/ui/index.tsx`：

```tsx
// 修前：只摘了 type/strong，code 被 {...props} 带进 <span>
const Text: any = ({ type, strong, style, children, ...props }: any) => {
  return !canRenderTDesign() ? <span {...props} style={mergedStyle}>…
```

`EvalPage` 用 `<Text code>`（TDesign 的"行内代码"语义）。fallback 分支既不认这个 prop，
又把它当 DOM 属性透传 → 布尔值 `code={true}` 触发 React 警告，而且**视觉上完全没有
等宽效果**（"代码"和正文长得一样）。

**已修**：抽出 `TEXT_INLINE_PROPS`（`code/delete/underline/mark/keyboard/italic/disabled`）
与 `splitInlineProps()`，fallback 分支只保留**有语义映射**的两个：`code` → 真 `<code>`
（等宽 + 读屏器可识别），`delete` → `line-through`；其余丢弃。`Title`/`Paragraph` 同样收敛。
并给 fallback 的 `<code>` 加上与 TDesign 分支共用的样式类 `.rag-inline-code`。
新增回归测试 `src/ui/FallbackProps.test.tsx`（该文件本来就钉着 Space/Progress/Select
的同类问题，这是它该管的事）。

## 2. 度量仪器：`frontend/scripts/visual-quality.mjs`

19 条路由 × 3 视口（1440/1366/375）× 2 主题 = **114 次页面加载**，每次采集：

| 指标 | 判据 |
|---|---|
| 横向溢出 | `documentElement.scrollWidth - innerWidth`；并逐个找越界元素 |
| 越界元素 | 右/左边缘超出视口的可见元素（排除横向滚动容器**及其后代**、a11y 隐藏元素） |
| 被截断文字 | `scrollWidth > clientWidth + 2` 且 `overflow` 非 visible、非 ellipsis |
| 字号分布 | 直方图 + 低于设计令牌下限（< 10px）的数量 |
| 对比度 | 逐元素按 WCAG 相对亮度算；**逐层向上解析真实背景**（见下） |
| 触控目标 | ≤480px 下 `button/a/select/[role=…]` 任一边 < 44px |
| 中英混排 | 含中文且含 ≥3 字母拉丁词、且**不在等宽/代码**里的可见短标签 |
| 主内容留白 | 主容器底部到最后一个文字元素的间距、相邻顶层块的**最大**间距 |
| 控制台 | pageerror + console error |

### 2.1 仪器自己先被修了三次（负反馈，已入台账）

一个没被验证过的指标比没有指标更危险，所以每次都用**已知答案的样本**回查：

1. **横向滚动容器的后代误报**：第一版把 `overflow-x: auto` 的容器本身排除了，却仍然
   量它的后代 → `/documents` 在 375px 报出 over=**893px**（其实是可横向滚动的 facet 列表）。
   **修订**：祖先链上任何一层是横向滚动容器就整支跳过。溢出元素 336 → 8。
2. **设计令牌内的字号被当成缺陷**：`--font-size-xxs: 10px` / `--font-size-xs: 11px`
   是**有意**的层级，第一版把 10–11px 全算作"过小文字"，报出 **2535** 条——
   数量大到无法指导任何决策。**修订**：只报低于令牌下限（< 10px）。2535 → 18。
3. **渐变背景导致的假对比度违规，以及它的过度修正**：`backgroundColor` 在渐变层上是
   透明的，逐层回溯会一路落到页面底色，于是"深色侧栏上的浅色文字"被算成
   "浅色文字压在白底上"→ ratio≈1.1。
   第一次修得过狠（祖先里**任何**一层带渐变就跳过），结果外壳根节点有渐变 →
   **7600 个元素全被跳过，对比度指标变成"永远 0 违规"的假绿**。
   **最终修订**：`resolveBackground()` 逐层向上，遇到**不透明背景色**就停并采用，
   遇到**带背景图**的层且此前还没确定背景才标记 unknown 跳过；跳过数单独上报
   （`对比度跳过(渐变底)`，实测 138，占比可接受）。
   → 对比度 1356（before）修复到 216（after）。

## 4. 诚实记录：还没做的

- **中英混排 383 条未处理**。抽样看下来要分两类：`Enter 发送 · Shift+Enter 换行`、
  `Dataset、QA 与版本` 这类是**合理保留**的专有名词；而
  `Workspace scope 已验证`、`Notification Center authority 暂不可用`、
  `Release authority 读取中` 这类是**把实现概念直接摆给用户**，应当中文化。
  度量本身不做这个区分（它只负责找出候选），逐条判断需要一轮单独的工作。
- **对比度剩余 216 条**：已不再集中在单一根因上，需要逐个看（多为 10–12px 的
  eyebrow/label 在浅底上）。
- **触控目标剩余 250 条**：不再有"每个页面都出现"的系统性项，剩下的是各页局部控件
  （`t-button--size-s` 24px 高、`sample-chip` 38px、`rag-select` 34px 等）。
- **深色主题的侧栏**走的是 `html[data-theme="dark"] .app-sider { background: #10141c }`，
  同一条 `.t-default-menu` 透明规则对它也生效，但本轮没有单独做深色专项复核。

## 5. 负反馈台账（R5 新增）

1. **视觉验收必须先关掉会盖住页面的东西**：任何"进页面就弹"的遮罩（新手引导、
   公告、cookie 条）都会让自动截图与自动度量静默地量错对象。判定方法很简单：
   量出来的"最高频问题元素"如果出现在**所有**页面上，先怀疑遮罩，再怀疑样式。
2. **指标要拿已知答案回查**：本轮的横向溢出（893px 假值）、字号（2535 假值）、
   对比度（7600 全跳过）三个假值都是靠"量出来的数大得不合理"回查出来的。
   **一个报出荒谬数字的指标，先修指标，再修产品。**
3. **修指标不能修成"永远绿"**：对比度那次过度修正把指标变成了恒 0——比误报更糟，
   因为它会让所有后续判断都朝着错误的方向"通过"。凡是加了跳过分支的指标，
   都必须把**跳过数**一起上报。
